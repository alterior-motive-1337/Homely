# Render cloud-primary deployment

Homely's cloud-primary deployment is designed so the homeowner device runs only a browser.

```text
browser
  |
  | HTTPS
  v
Render web service
  |
  +-- Homely Node server
  +-- ephemeral SQLite working database
  +-- optional OpenAI agent
  |
  +----> Google Drive / Homely Backups
```

The SQLite database remains Homely's source of truth while the process is alive. Google Drive is the off-site recovery layer. Important committed transactions trigger an immediate verified SQLite backup; a periodic backup also runs while the service is awake. The first deployment is allowed to boot in degraded backup mode so missing Google credentials do not prevent the service from starting.

## Why backup-on-commit matters on Render Free

A free Render web service can spin down after inactivity, and its local filesystem is ephemeral. Homely therefore does not rely on the local SQLite file surviving a restart. On boot it restores the newest valid Drive backup before migrations or seeding run.

If no Drive backup exists yet, Homely creates the demo database and immediately uploads the first backup before it begins serving traffic.

## 1. Prepare Google Drive credentials

Create or select a Google Cloud project dedicated to Homely.

1. Enable the **Google Drive API**.
2. Configure the OAuth consent screen.
3. During setup you can add the Google account that will own the Homely backup folder as a test user.
4. **Before relying on Homely backups long-term, move the OAuth app to “In production”.** Google refresh tokens issued to an external OAuth app left in Testing normally expire after 7 days. Homely's backup design requires a long-lived refresh token.
5. Create an **OAuth 2.0 Client ID** of type **Web application**.
6. Add this authorized redirect URI to that client:
   `https://developers.google.com/oauthplayground`

Homely only requests:

```text
https://www.googleapis.com/auth/drive.file
```

That scope lets Homely manage files it creates or files explicitly shared with it; it does not grant unrestricted access to the entire Drive.

## 2. Generate the long-lived refresh token

Open Google's OAuth 2.0 Playground.

1. Open the configuration panel.
2. Enable **Use your own OAuth credentials**.
3. Enter the Homely OAuth client ID and client secret.
4. Use **Server-side** flow.
5. Set access type to **Offline**.
6. Force the consent screen for this authorization.
7. In Step 1, enter:
   `https://www.googleapis.com/auth/drive.file`
8. Authorize the API using the Google account that should own Homely backups.
9. Exchange the authorization code for tokens.
10. Copy the **refresh token**.

Do not commit the client secret or refresh token anywhere. They go directly into Render's secret environment-variable prompts.

## 3. Create the Render Blueprint

In Render:

1. Choose **New > Blueprint**.
2. Connect the `noob-express3000/Homely` repository.
3. Render will detect the root `render.yaml`.
4. During initial Blueprint creation, provide these secret values when prompted:
   - `HOMELY_OWNER_PASSWORD` — a strong password used to enter Homely.
   - `GOOGLE_CLIENT_ID`
   - `GOOGLE_CLIENT_SECRET`
   - `GOOGLE_DRIVE_REFRESH_TOKEN`
5. Apply the Blueprint.

`HOMELY_SESSION_SECRET` is generated by Render and never needs to be supplied manually. `BACKUP_REQUIRED` is intentionally false for the first deployment so Homely can come online before Drive authorization is complete. Once Drive status is confirmed healthy, change `BACKUP_REQUIRED=true` in Render if you want future boots to fail closed whenever recovery storage is unavailable.

The Blueprint leaves voice disabled. OpenAI is enabled at the feature flag level, but remains unavailable until `OPENAI_API_KEY` is supplied as a Render secret; this lets the agent come online without another code change once the key is configured.

## 4. First boot behavior

At startup Homely performs this sequence:

```text
validate owner/backup configuration
        |
        v
is homely.db missing?
   |           |
  yes          no
   |           |
   v           |
query Drive    |
   |           |
latest backup? |
 |        |    |
yes       no   |
 |        |    |
restore   seed |
 |        |    |
verify    backup
   \      /
    migrate
       |
       v
start HTTP server on 0.0.0.0:$PORT
```

A downloaded database must pass SQLite `PRAGMA integrity_check` before it becomes the working database.

## 5. Verify the deployment

Open the Render URL. Homely should show the owner login screen before any property data is exposed.

After signing in:

1. Open the application normally.
2. Check the integration status from the UI/API.
3. Create a harmless test issue.
4. Preview it.
5. Approve the transaction.
6. Open Google Drive and confirm a **Homely Backups** folder exists with a recent `homely-*.db` file.

The commit response is not rolled back if Drive is temporarily unavailable. Homely records backup health separately and retries on later backup opportunities. This avoids duplicating an already-committed home transaction.

## 6. Recovery test before using real data

Before treating the deployment as authoritative, perform one controlled recovery test:

1. Commit a recognizable test change.
2. Confirm a newer Drive backup exists.
3. Trigger a Render restart/redeploy so the ephemeral working filesystem is replaced.
4. Wait for Homely to boot.
5. Sign in and confirm the test change is still present.

That proves the restore path, not merely the upload path.

## Optional Google Drive document connection

The backup refresh token is enough for background database backups.

If the interactive Google Drive document picker is also used on Render, add the deployed callback URL to the Google OAuth client and set this environment variable manually in Render:

```text
GOOGLE_DRIVE_REDIRECT_URI=https://<your-render-host>/api/google-drive/callback
```

The OAuth client must contain that exact redirect URI.

## Optional OpenAI agent

After the base deployment is stable:

1. Add `OPENAI_API_KEY` as a Render secret.
2. Save and deploy. `AI_ENABLED=true` is already part of the Blueprint.

OpenAI still receives proposal-only Homely tools. It cannot directly commit or reverse property state.

## Upgrade path

The free setup deliberately uses an ephemeral SQLite working copy plus Drive recovery because it costs less infrastructure.

If a persistent Render disk is added later, point `HOMELY_DB_PATH` at the disk mount. The Drive backup layer remains useful as off-site disaster recovery and does not need to be removed.
